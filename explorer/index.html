Classify support tickets through one model gateway

Two Expanso Edge pipelines read the same four tickets and ask the same local gateway to classify each one. They differ in where the request is built.

The HTTP pipeline builds the request in pipeline YAML with a branch. The subprocess pipeline hands each ticket to a small Python client that stays alive for the whole run. Both end with the same record: category, sentiment, priority, and where the answer came from.

The gateway replays answers that were recorded once and committed to the repository, so a run makes no model call. A ticket with no recorded answer is refused, and both pipelines turn that refusal into an error record instead of guessing.

HTTP in the pipeline

          
Choose it when the request is a few lines of mapping. There is no child process to start, supervise or stop, and the whole flow is visible in the Expanso Cloud graph.

        

        

          
Python client

          
Choose it when validating the request or parsing the answer belongs in ordinary code with its own unit tests. The cost is one long-lived process on the node and Python 3.11 or newer.

        

      

      
The earlier version of this demo also compared three model providers directly. Every model request now goes through the gateway, so that comparison was removed by captain decision and is recorded in public-removals/ instead of being repeated here.

    


    

      
Run it

      
You need Docker and a clone of this repository. No credential and no sibling checkout are needed. Each command starts the replay gateway and Expanso Edge in one container, deploys the pipeline, prints four records, and exits 0 on its own.

      

        
HTTP pipeline


docker compose run --rm gateway-http

      

      

        
Subprocess pipeline


docker compose run --rm gateway-subprocess

      

      
To regenerate this explorer and the dated run report from a fresh run, use the command below. It fails if the committed explorer data no longer matches what the pipelines produce.

      

        
Prove the run


uv run -s scripts/prove.py --check --node

      

    


    

      
Deploy to Expanso Cloud

      
The node runs two unprivileged containers on a read-only root that share one network namespace. The replay gateway listens on loopback inside it and publishes no port, so the address the pipelines call, 127.0.0.1:18157, is the colocated gateway. The Edge identity and its message buffer persist in a named volume.

      
    
        
  1. 
          Save the bootstrap token from Expanso Cloud in .expanso-bootstrap-token. The file is git-ignored, and Compose hands it to the enroll container as a secret, never as a command-line flag. On Linux, make uid 1000 its owner.

  2.

  --profile enroll run --rm enroll

    docker compose -f deploy/docker-compose.node.yaml up -d

  4. 
          Deploy a pipeline with your project's Expanso CLI profile. The job selector demo: demo-agents-sdk matches the node label set in config/edge-node.yaml.
          
    
            
    Deploy
    

    expanso-cli job deploy pipelines/gateway-http.yaml
    
          
    
        
    5. 
        
  5.
